# 接続トラブルシューティング

2台目のデバイス（スマートフォンや別のPC）がMac上のサーバーに接続できない場合、以下の原因が考えられます。

## 1. QRコードのアドレス問題 (0.0.0.0)

### 現象
QRコードに表示されているアドレスが `0.0.0.0:<ポート番号>` となっている場合、**外部デバイスからは接続できません**。

### 原因
`0.0.0.0` は「そのデバイス自身（ローカルホスト）」を指す特殊なアドレスです。
Mac（サーバー）自身にとっては「全てのネットワークインターフェースで待ち受ける」という意味で正しいですが、
スマートフォン（クライアント）が `0.0.0.0` に接続しようとすると、スマートフォン自身に接続しようとして失敗します。

### 対策
QRコードには、Macの **LAN内IPアドレス**（例: `192.168.1.10` など）を表示する必要があります。
サーバー起動時に表示されるQRコードが `0.0.0.0` のままでは接続できないため、以下のいずれかを行ってください。

1.  **手動入力**: スマートフォン側のクライアントアプリで、IPアドレスを手動で入力できる場合は、MacのIPアドレス（システム設定 > ネットワーク で確認可能）を入力してください。
2.  **コード修正**: `Base2.dart` の実装を修正し、`0.0.0.0` ではなく `NetworkInterface.list` から取得した実際のIPアドレスをQRコードに埋め込むように戻してください。

## 2. macOSのローカルネットワークプライバシー

### 現象
IPアドレスが正しくても接続できない（タイムアウトする）。

### 原因
macOS Sequoia以降などでは、アプリケーションがローカルネットワーク上の他のデバイスと通信する際にユーザーの許可が必要です。
また、ファイアウォールが外部からの接続をブロックしている可能性があります。

### 対策
1.  **ローカルネットワーク許可**: アプリ初回起動時に「ローカルネットワーク上のデバイスの検索と接続を許可しますか？」というダイアログが出た場合、「許可」を選択している必要があります。システム設定 > プライバシーとセキュリティ > ローカルネットワーク から確認・変更できます。
2.  **ファイアウォール**: システム設定 > ネットワーク > ファイアウォール で、このアプリへの着信接続が許可されているか確認してください。

## 3. ネットワーク分離（AP Isolation）

### 現象
IPアドレスも正しく、Mac側の設定も問題ないが接続できない。

### 原因
Macとスマートフォンが接続しているWi-Fiネットワークの設定で、デバイス間の通信がブロックされている場合（ゲストWi-Fiや、カフェの公衆Wi-Fiなど）。

### 対策
両方のデバイスが、デバイス間通信が許可されている同一のプライベートWi-Fiネットワーク（自宅やオフィスのメインSSIDなど）に接続していることを確認してください。
