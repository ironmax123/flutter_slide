# マルチウィンドウ実装レポート

本プロジェクトにおけるFlutterデスクトップ（macOS）でのマルチウィンドウ実装について、そのアーキテクチャと詳細をまとめます。

## 1. 使用ライブラリと選定理由
本プロジェクトでは、マルチウィンドウ管理のために **`multi_window_native`** パッケージを採用しました。

*   **選定理由**: `window_manager`などの他パッケージと比較して、ウィンドウ生成の挙動がネイティブ寄りであり、今回の要件に適していると判断しました。
*   **構成**:
    *   **Main Window**: アプリケーションのメイン画面（スライド表示）。
    *   **Secondary Window**: コントローラー画面（`Base2`ウィジェット）。

## 2. アーキテクチャ概要

### ウィンドウ生成とルーティング
`main.dart` にて、起動引数（arguments）を解析し、ウィンドウの種類を決定しています。
*   引数なし: メインアプリ（`MyApp` / `Base`）を起動。
*   引数 `secondScreen`: サブウィンドウ用の `Base2` を起動。

```dart
void main(List<String> args) async {
  if (args.isNotEmpty && args[0] == 'secondScreen') {
    // サブウィンドウとしての起動
    runApp(const MaterialApp(home: Base2()));
  } else {
    // メインウィンドウとしての起動
    runApp(const ProviderScope(child: MyApp()));
  }
}
```

## 3. ネイティブ連携（macOS）
`multi_window_native` の標準機能では不足していた「ウィンドウリサイズ」や「状態共有」を実現するため、macOSネイティブ側（`AppDelegate.swift`）に独自の `MethodChannel` を実装しました。

### A. ウィンドウリサイズ (`.../window_control`)
サブウィンドウは起動時に特定のサイズ（380x460）にする必要がありました。
Dart側から `resizeWindow` メソッドを呼び出し、ネイティブ側で `NSWindow` のフレームサイズを変更しています。

### B. サーバー状態の共有 (`.../server_state`)
メインウィンドウとサブウィンドウ間で、引数を使わずに「接続先ポート番号」を共有するため、OSレベルでの状態管理を実装しました。

1.  **Base2 (Server)**: サーバー起動時に `setServerPort` を呼び出し、ポート番号を通知。
2.  **AppDelegate**: 通知を受け取り、`onServerPortChanged` イベントを **全ての** 起動中Flutterエンジンに対してブロードキャスト。
3.  **BaseViewModel (Client)**: イベントを受信し、通知されたポートへ自動接続。

## 4. 通信アーキテクチャ（リモート操作）
メインウィンドウ（スライド）とサブウィンドウ（コントローラー）間の通信には、**TCPソケット**を使用しています。

*   **Server (Base2)**:
    *   指定ポート（デフォルト8000、変更可能）で `ServerSocket` をリッスン。
    *   クライアント（メインウィンドウや外部端末）からの接続を管理。
    *   受信したコマンド（`next`, `previous`）を接続中の**全クライアント**へブロードキャスト。
    *   外部端末接続用に、QRコード（`0.0.0.0:Port`）を表示。
*   **Client (BaseViewModel)**:
    *   ネイティブ側からの「サーバー起動通知」をトリガーに接続。
    *   受信したメッセージに応じてスライド操作（`nextPage`, `previousPage`）を実行。

## 5. まとめ
このアーキテクチャにより、以下のメリットを実現しました。

*   **疎結合**: ウィンドウ生成時に引数でポート番号を渡す必要がなく、各ウィンドウが独立して動作しつつ状態を共有できる。
*   **拡張性**: TCP通信を採用したことで、サブウィンドウだけでなく、同一ネットワーク上のスマートフォン等からもスライド操作が可能。
*   **ネイティブ機能の活用**: 標準プラグインで不足する機能を、Swiftコードによる拡張で補完。
